# 여행 일정표 만들기 (질의 → 추천 → 확정 → HTML 완성, 한 번에)

**결과물은 HTML이다.** `trip.json`을 작성하면 `build.py`가 두 가지를 만든다.
- **가족 공유 파일** `share/<제목>.html` — 이미지까지 모두 들어간 HTML 한 개. 다운로드 폴더에도 자동 복사. 카톡으로 보내면 받은 가족이 열어서 바로 쓴다(인터넷 없어도 열림).
- **웹 앱** `index.html` + `sw.js` … — 원하면 Vercel에 배포해 주소로 공유(홈 화면 설치·오프라인).

화면(하단 탭 **일정 > 식사 > 정보 > 티켓 > 쇼핑 > 준비**)은 `template/index.html`이 그리므로, 여행마다 화면 코드를 쓰지 않고 **데이터만 만든다.**

> ⛔ **금지:** 일정·계획서를 Markdown(.md) 파일로 만들거나, `Artifact` 도구로 게시하거나, 별도 HTML을 손으로 새로 짜서 전달하지 않는다. 사용자에게 주는 것은 오직 `build.py`가 만든 HTML(공유 파일·웹 앱)이다. 중간 요약은 채팅에 짧게만 쓴다.

```
~/.claude/skills/trip-planner/
├── SKILL.md                     ← 지금 문서(절차)
├── references/planning-rules.md ← 동행·국내/해외·이동수단별 기획 규칙  (1단계 시작 전에 읽기)
├── references/trip-schema.md    ← trip.json 형식                      (4단계 전에 읽기)
├── scripts/build.py             ← 검증 + 웹 앱 + 가족 공유 파일 생성 (사이트면 메인 페이지도 갱신)
├── scripts/build_home.py        ← 여러 여행을 묶는 메인 페이지(여행 목록) 생성
├── scripts/verify.mjs           ← 헤드리스 크롬으로 모든 탭·공유 파일 점검
├── examples/osaka-sample/       ← 모든 탭을 쓰는 예시 trip.json + assets  (4단계 전에 열어 보기)
└── template/                    ← index.html · sw.js · vercel.json · home.html · site-* ...
```

**사이트 모드 (여러 여행을 주소 하나로):** 폴더에 `site.json`이 있으면 그 폴더가 사이트다.
```
<사이트폴더>/                 ← git 저장소 · Vercel Root Directory는 비워 둠(저장소 맨 위)
├── site.json                 ← { "title": "OurTrip", "subtitle": "..." } — 앱 이름이 됨
├── index.html                ← 메인 페이지(여행 목록 + 앱 설치 버튼) — build_home.py가 생성
├── manifest.webmanifest, sw.js, icons/ ← 설치형 앱(범위 = 사이트 전체, 아이콘은 template/site-icons)
├── vercel.json, .vercelignore ← build_home.py가 생성 (스킬 코드·md·trip.json은 배포 안 함)
├── gyeongju-2026-10/         ← 여행 하나 = 폴더 하나 → https://<주소>/gyeongju-2026-10/
└── osaka-2026-11/
```
여행 폴더에서 `build.py`를 돌리면 메인 페이지가 자동으로 갱신된다. 메인은 설치형 앱(안드로이드는 '앱 설치' 버튼으로 바로 설치, iOS·카톡 브라우저는 안내 화면)이고, 여행 표지에는 '‹ 앱 이름' 돌아가기 링크가 붙는다. 앱의 경로는 모두 상대경로라 사이트 안(`/<id>/`)에서도, 폴더 단독 배포(`/`)에서도 동작하고, 서비스워커는 여행 폴더 범위로 따로 설치되며 캐시도 여행별로 분리된다.

## 진행 원칙 (반드시 지킨다)

1. **모든 입력은 `AskUserQuestion`으로 받는다.** "아래 양식을 채워 주세요" 같은 텍스트 양식이나 열린 질문을 일반 메시지로 보내지 않는다. 자유 입력이 필요하면 사용자가 보기의 "Other"를 쓰면 된다.
2. **보기는 추론해서 만든다.** 고정된 보기 목록을 쓰지 말고, 이전 답변·오늘 날짜(시즌·공휴일)·동행 특성·이동수단으로 그럴듯한 후보를 골라 제시한다. 가장 맞는 보기를 맨 앞에 두고 라벨 끝에 `(추천)`, description에 **추천 이유**를 한 줄로 쓴다.
3. **정해진 것이 없으면 대신 정해 준다.** 장소·코스·숙소 위치·식사를 사용자가 정하지 않았으면 "추천으로 제안해 드릴까요?"를 보기로 넣고, 고르면 조사해서 구체적인 안을 만들어 다시 고르게 한다.
4. **한 번에 최대 4문항**, 서로 독립인 질문끼리 묶는다. 앞 답에 따라 달라지는 질문은 다음 라운드로 넘긴다.
5. **이미 아는 것은 다시 묻지 않는다.** 호출 인자(`$ARGUMENTS`)와 대화에 나온 값은 채워 두고 건너뛴다. 단, 애매하면 그 해석을 `(추천)` 보기로 놓고 확인한다.
6. **멈추지 않고 끝까지 간다.** 마지막 확인에서 "이대로 만들기"를 받으면 조사·작성·생성·검증·전달까지 중간에 넘기지 않고 끝낸다. 끝은 항상 "공유 파일 HTML 경로"다.
7. 사실(운영시간·휴무·이동 시간)은 추론하지 않고 **웹 검색으로 확인**한다. 추론은 "무엇을 제안할지"에만 쓴다.

질의 중에는 매 라운드 앞에 지금까지 정해진 것을 한 줄로 보여 준다. 예: `✔ 국내 · 부모님+배우자 · 렌터카 · 11/7~9(2박3일) · 경주`

## 1단계 · 기본 정보 질의

### 라운드 A — 여행의 틀 (4문항 한 번에)
| header | 질문 | 보기 만드는 법 |
|---|---|---|
| 국내/해외 | 이번 여행은 국내인가요, 해외인가요? | `국내` / `해외` |
| 동행 | 누구와 함께 가나요? (모두 선택, multiSelect) | `부모님` / `배우자·연인` / `아이` / `친구` (혼자·동료는 Other) |
| 기간 | 며칠 동안 가나요? | `당일` / `1박 2일` / `2박 3일` / `3박 4일 이상` |
| 출발일 | 언제 출발하나요? | 오늘 기준 가까운 **실제 날짜 후보 3개**(다가오는 주말, 연휴·공휴일, 다음 달 주말). 예: `10/9(금) 출발 · 한글날 연휴 (추천)` — 정확한 날짜는 Other |

### 라운드 B — 누구와 · 어떻게 (A 답에 따라 구성)
| header | 질문 | 보기 만드는 법 |
|---|---|---|
| 인원 | 몇 명이 가나요? | 동행 선택으로 추정한 구성 2~3개. 예: `4명 · 부모님 2 + 우리 부부 (추천)` / `3명` / `5명 이상` |
| 이름 표시 | 앱에 사람을 어떻게 표시할까요? | `관계로 표시 (엄마·아빠·나…) (추천)` / Other로 "이승훈, 김지희…"처럼 이름 입력 |
| 아이 나이 | (아이 선택 시만) 아이 나이대는? | `0~3세` / `4~6세` / `7~12세` / `13세 이상` |
| 이동수단 | 여행지에서 어떻게 움직이나요? (multiSelect) | 국내/해외·기간·동행으로 추론. 국내+부모님 → `렌터카 (추천)`·`KTX·기차`·`버스·택시`. 해외 → `비행기+대중교통 (추천)`·`비행기+렌터카`·`투어 버스` |

### 라운드 C — 어디로
**장소가 정해지지 않았으면** 질문: "어디로 갈까요?" header `장소`
- 보기 3개: 시기(계절·축제)·동행·기간·이동수단에 맞는 **구체적인 지역 추천**. description에 이유. 예: `경주 (추천) — 11월 단풍, 평지 위주라 부모님 걷기 편함, 2박3일에 적당`
- 4번째 보기: `추천받고 싶어요 (조건 더 말하기)` → 테마를 묻는 라운드(`휴식`/`관광`/`먹거리`/`자연·액티비티`, multiSelect)를 거쳐 다시 지역 3개 제시.
- 이미 장소를 말했으면 건너뛴다. 범위가 넓으면("일본") 세부 지역을 같은 방식으로 묻는다.

### 라운드 D — 코스
질문: "정해 둔 코스가 있나요?" header `코스`
- `추천 경로로 제안해 드릴까요? (추천)` — 정해진 경로가 없을 때 기본값
- `가고 싶은 곳이 몇 군데 있어요` → Other로 장소 이름만 받고, 나머지는 추천으로 채운다
- `코스가 다 정해져 있어요` → Other로 받은 순서를 그대로 쓴다
- 함께 묻기(독립 문항): `여행 스타일` — `여유롭게 (하루 2~3곳) (추천)` / `보통 (3~4곳)` / `알차게 (5곳 이상)` — 추천은 동행 규칙(planning-rules.md 1절)으로 고른다.

### 라운드 E — 예약 현황 (multiSelect)
"이미 예약한 것이 있나요?" header `예약` — `아직 없어요` / `교통편(항공·기차)` / `숙소` / `렌터카·투어`
- 예약한 항목이 있으면 다음 라운드에서 항목별로 묻는다(편명·시간, 숙소 이름 등). 보기는 검색으로 찾은 실제 후보(예: 그 날짜의 김포→제주 아침 편 시간대, 해당 지역 숙소 이름)로 만들고, 정확한 값은 Other로 받는다.
- 숙소가 없으면 `숙소 위치`를 묻는다: 코스 동선상 유리한 지역 2~3곳을 이유와 함께 보기로(예: `보문단지 (추천) — 주차 편하고 2·3일차 동선 중간`).
- 식단 제한·꼭 피할 것은 `먹거리` 질문 하나로: `특별히 없음 (추천)` / `해산물 X` / `매운 음식 X` / `채식` (multiSelect).
- 식사 방식: header `식사` — "정해 둔 식사가 있나요?" (multiSelect) `없어요 · 끼니마다 동선 근처 2곳 추천 (추천)` / `예약·정해 둔 식당 있어요` (→ Other로 가게·날짜·시간) / `숙소 조식 포함` / `아침은 간단히(편의점·카페)`
- 쇼핑 탭: header `쇼핑` — "쇼핑 리스트도 만들어 드릴까요?" `지역 특산품·선물 추천 (추천)` / `약·생활용품 위주` / `면세·브랜드 위주` / `필요 없어요` (multiSelect, 살 것이 정해져 있으면 Other). 고른 방향으로 조사해 `shop`(매장별 칩, 반입 금지 경고 포함)을 채운다.

### 빠진 항목 확인
아래가 모두 정해졌는지 확인하고, 빈 것은 **그 항목만** 같은 방식(추천 보기 포함)으로 다시 묻는다.
`region` · `travelers`(관계·인원·표시 이름) · `transport` · `dates` · `destination` · `course`(추천 수락도 유효)

## 2단계 · 추천 경로 만들기와 다듬기

1. `references/planning-rules.md` 기준으로 조사한다(운영시간·휴무·이동 시간·날씨·주차). 3일 이상이면 날짜별로 `Agent`(general-purpose)를 병렬로 띄워 조사하고 결과(출처 포함)만 받는다.
2. **경로안 2~3개**를 만든다. 예: `A. 역사 중심 (추천)`, `B. 자연·바다 중심`, `C. 먹거리 중심`. `AskUserQuestion`(header `경로안`)으로 고르게 하고, 각 보기의 `preview`에 날짜별 동선을 보여 준다:
   ```
   1일 11/7(금)  서울 → 경주(차 4h) · 불국사 · 보문호 산책
   2일 11/8(토)  석굴암 · 황리단길 점심 · 대릉원 · 동궁과 월지 야경
   3일 11/9(일)  양동마을 · 점심 후 귀가
   하루 2~3곳 · 걷기 최대 40분 · 휴식 매일 14시
   ```
   사용자가 정한 코스가 있으면 그 순서를 지킨 1안 + 보완안 1개만 제시한다.
3. **세부 일정 확인**: 고른 안을 시간표(시각·장소·이동·식사 줄)로 펼쳐 보여 주고 질문한다. header `일정 확인` — `이대로 좋아요 (추천)` / `바꾸고 싶은 날이 있어요` → 날짜를 multiSelect로 고르게 한 뒤, 그 날의 대안(장소 교체·순서 변경·여유 추가)을 추천 보기로 제시. 만족할 때까지 반복한다.
4. **식사 — 정해진 것은 그대로, 없으면 끼니마다 2곳 추천 → 고르기**
   - 정해진 식사(예약 식당·숙소 조식 등)는 `confirmed: true`(예약이면 `reserved: true`)로 넣고 다시 묻지 않는다.
   - 나머지 끼니는 경로가 확정된 뒤 **앞뒤 일정 장소 근처**(걸어서 10~15분 또는 다음 이동 경로 위)에서 후보 **2곳**을 조사한다. 그 요일·시간에 영업하는지 웹 검색으로 확인하고, 먹거리 제한·동행(부모님 → 의자석·대기 짧음, 아이 → 아이 메뉴)을 반영한다. 2곳은 성격을 다르게: `현지 대표 메뉴` 하나 + `빠르고 무난한 곳` 하나.
   - 먼저 header `고르는 시점`: `지금 같이 고르기 (추천)` / `여행 중 앱에서 고르기`.
   - **지금 고르기**: 끼니마다 `AskUserQuestion` 문항 하나(header 예: `11/14 중식`, 최대 4끼니씩 묶음). 보기 = 후보 2곳(label: `가게 · 대표 메뉴`, description: `위치(앞뒤 일정 기준 거리) · 영업시간 · 가격 · 추천 이유`) + `앱에서 고를게요`. 고른 곳은 `confirmed: true`, 다른 곳은 대안 후보로 남긴다. Other로 다른 가게를 말하면 조사해서 확정으로 넣는다.
   - **앱에서 고르기**: 두 곳 모두 `confirmed` 없이 넣는다 → 일정표에 "2곳 중 고르기"로 표시, 식사 탭에서 "이걸로 정하기".
   - 날마다 `nearby`(카페·간식·대안 식사)도 1~2곳씩 — 식사 탭 아래 "그 밖의 근처 가게"로 나온다.
5. **탭별 데이터 준비** — 화면의 모든 탭이 채워지도록 조사 단계에서 함께 모은다(질문 없이):
   - 정보: 숙소·주요 목적지 `places`(해외는 현지어 이름·주소), 날짜별 동선 `maps`, 긴급·예약처 `contacts`, `bookings`, 해외는 `phrases` 6~10개, `sections`(결제·전기·교통카드 등)
   - 티켓: 이동수단·예약에 맞는 `ticket_groups`(해외면 사람별 `입국 QR` 그룹 포함)와 카드. 아직 없는 티켓은 "예약 후 입력" + 사진 칸
   - 준비: 출발 전 / 필수품 / 옷차림(날씨 기반) / 여행 중 — planning-rules.md의 국내·해외·이동수단 항목 반영

## 3단계 · 최종 확인
정리 표(기본 정보 + 날짜별 한 줄 + 저장 위치)를 보여 주고 `AskUserQuestion`(header `확인`):
`이대로 만들기 (추천)` / `조금 더 고칠게요`
- 저장 위치 기본값: 현재 폴더(또는 그 상위)에 `site.json`이 있으면 **그 사이트 폴더 바로 아래** `<여행-id>` — 메인 페이지에 자동으로 추가된다. 없으면 현재 작업 폴더의 상위 폴더 아래 `<여행-id>` (예: `~/projects/gyeongju-2026-11`). 현재 폴더가 이미 다른 여행 앱이면 그 안에 만들지 않는다.

**"이대로 만들기" 이후는 질문 없이 끝까지 진행한다.**

## 4단계 · trip.json 작성 (`references/trip-schema.md`와 `examples/osaka-sample/trip.json`을 먼저 읽는다)
- `mkdir -p <폴더>/assets`. 사용자가 준 티켓·QR 이미지가 있으면 `assets/`로 복사(영문 소문자 파일명).
- `intake`에 1단계 답을 저장한다. 표시 이름을 관계로 정했으면 `name`에 관계("엄마")를 넣는다. `course`에는 확정한 경로안 요약을 쓴다.
- 동행·이동수단·국내/해외 규칙을 반영해 `days/meals/places/tickets/info/checklist`를 채운다.
- 확인 못 한 값(예약번호 등)은 지어내지 않고 `tip`에 "예약 후 입력"/"확인 필요".

## 5단계 · 생성과 검증
```bash
python3 ~/.claude/skills/trip-planner/scripts/build.py <폴더> --check   # 검증만 — 실패하면 trip.json 고치고 반복
python3 ~/.claude/skills/trip-planner/scripts/build.py <폴더>           # 웹 앱 + share/<제목>.html + 다운로드 폴더 복사
node ~/.claude/skills/trip-planner/scripts/verify.mjs <폴더> <스크래치패드>/shots   # 브라우저 점검
```
- `verify.mjs`는 탭 순서, 모든 탭·하위 탭, 일정 카드 수, 주소 카드, 식사 확정 → 일정 반영, 준비 체크, 사진 추가, "사진 포함 파일 보내기", 공유 파일(file://) 열기, 콘솔 오류를 확인한다. **❌가 하나라도 있으면 원인을 고치고 다시 실행**한다.
- 스크린샷 중 일정·정보·티켓 화면 2~3장을 직접 보고 글자 넘침·빈 화면이 없는지 확인한다.
- 크롬이 없어 verify를 못 돌리면(종료 코드 2) 그렇다고 보고한다.

## 6단계 · 전달 (HTML)
최종 보고는 짧게, 아래 순서로:
1. **가족 공유 파일 경로** — build.py 출력의 `📦 가족 공유 파일`과 다운로드 폴더 복사 경로(Windows면 `C:\Users\<사용자>\Downloads\<제목>.html`).
2. 보내는 법 — "이 파일을 카톡 '나에게 보내기' 또는 가족방에 파일로 보내면, 받은 사람은 파일을 눌러 브라우저로 열면 됩니다. 인터넷 없이도 열려요."
3. 날짜별 한 줄 요약, "확인 필요/예약 후 입력"으로 남긴 항목
4. 가족이 할 일 — 티켓 탭에서 입국 QR·티켓 사진 추가 → "사진 포함 파일 보내기"로 다시 공유
5. 마지막으로 `AskUserQuestion`(header `다음`): `여기까지 (추천)` / `웹 주소로도 배포 (Vercel)` / `git 커밋` — **배포·커밋은 고른 경우에만** 실행한다.
   - 사이트 모드: 커밋 후 `git push`하면 Vercel이 자동으로 다시 배포한다(프로젝트 하나, Root Directory 비움). 새 여행 주소는 `https://<사이트 주소>/<여행-id>/`.
   - 단독 폴더: 여행 폴더에서 `vercel --prod` 결과 주소를 알려 준다.

## 수정 요청이 올 때
trip.json만 고치고 `build.py <폴더>` → `verify.mjs <폴더>`를 다시 실행해 새 공유 파일을 전달한다. index.html이나 share 파일을 직접 고치지 않는다(다시 생성하면 덮어써짐).
바꿀 내용이 애매하면 위와 같은 방식(추천 보기)으로 묻는다.
화면 자체를 바꿔야 하면 `template/index.html`을 고치고 모든 여행에 반영됨을 알린다.
